# Правила работы с проектом NXai

Для Claude Code. Ниже — то, что в этом проекте уже проверено или чинилось после ошибки.
Не абстрактные «лучшие практики»: почти каждый пункт стоил разбора.

Устройство системы — [ARCHITECTURE.md](ARCHITECTURE.md). Развёртывание —
[DEPLOY.md](DEPLOY.md). Журнал решений — [ROADMAP.md](ROADMAP.md).

**NXai — не NX.** Это второй проект того же владельца, и репозитории лежат рядом. У NX
своя ветка, свои сервисы и свои команды деплоя; перепутать их легко и дорого. Если рядом
оказался клон NX — он **только для чтения**, ни одного файла в нём менять нельзя.

---

## Чем NXai отличается от NX

| | NX Automatron | NXai |
| --- | --- | --- |
| Откуда контент | живые авторы пишут в канал-черновик | чужие Telegram-каналы, отбор по виральности |
| Единица работы | редакция целиком | **тема** (ниша) со своим ботом, персоной, расписанием |
| Люди-авторы | есть, с рейтингами и рассылками | **нет вовсе** |
| Ветка | своя | `main` |

Отсюда правило: решения NX переносятся не дословно. Всё, что завязано на живых авторов
(предложка, рейтинги, персональные отчёты), в NXai не нужно.

## Общение

**Отвечать по-русски.** Проект, интерфейс, комментарии и журнал — на русском.

**Владелец — не программист**, но проверяет результат руками, часто с телефона, часто
присылает скриншоты. Отсюда:

- объяснять результат через то, что он увидит в панели или в боте, а не через имена
  функций;
- если задача сформулирована симптомом («бот присылает не то») — сначала найти причину
  в коде, потом отвечать; догадка без проверки хуже отсутствия ответа;
- не задавать блокирующих вопросов там, где можно принять разумное решение и назвать его.

**Никогда не указывать идентификатор модели** — ни в коммитах, ни в коде, ни в
документации. Только в чате, если спросили прямо.

## Ветка и коммиты

Ветка разработки — **`main`**, пушим прямо в неё. Pull request не создавать, пока не
попросили.

Формат сообщения: заголовок `тип(область): краткая суть`, затем абзац о том **что было
не так и что стало** (не перечисление файлов — они видны в диффе).

Пуш: `git push -u origin main`. При сетевой ошибке — до 4 повторов с задержкой 2/4/8/16 с.
Если пуш отклонён — `git fetch` + `git rebase origin/main`, проверить, что обе правки на
месте. Не делать force-push.

## Порядок сдачи работы

Гонять только то, что относится к изменению:

| Что менялось | Что прогонять |
| --- | --- |
| только `web/` | `npm run build && npx tsc --noEmit && npm run lint` + живая проверка |
| сервисы, роутеры, бот, планировщик | целевые тесты → полный прогон → `ruff check .` |
| модели | то же плюс новая миграция и `alembic upgrade head` |
| только `ROADMAP.md` / `docs/` / комментарии | ничего |

```bash
# 1. Тесты на затронутое — идут секунды
python -m pytest -q tests/test_daily_batch.py

# 2. Полный прогон. Без пайпа: `pytest | tail` возвращает код tail, и «exit 0»
#    ничего не значит.
python -m pytest -q > /tmp/run.log 2>&1; echo "exit=$?"; tail -3 /tmp/run.log

# 3. Линтер
ruff check .

# 4. Фронтенд
cd web && npm run build && npx tsc --noEmit && npm run lint
```

**Никогда не запускать два прогона одновременно.** База одна, тесты пишут в те же
таблицы — параллельный запуск даёт сотни падений, не имеющих отношения к коду.

**Живая проверка, если изменение видно пользователю.** Тесты проверяют логику, а не то,
что кнопка отрисовалась и нажимается. Порядок — в разделе «Окружение» ниже.

## Код

**Комментарии объясняют «почему», а не «что».** Это главная стилевая черта проекта.
Плохо: «увеличиваем счётчик». Хорошо: «берём пул вчетверо шире заказа, потому что
топ-N по виральности на практике даёт N постов про один инфоповод».

**Сначала посмотреть, как это уже сделано.** Конвенции, которые легко нарушить:

- `core/` **не импортирует** `interfaces/`. Форматирование под Telegram живёт в
  `interfaces/`; сервисы возвращают сырые данные. Исключение — `core/services/tg_format.py`:
  это преобразование текста, а не интерфейс, и его зовёт в том числе публикация;
- UUID из `callback_data` в хендлерах бота парсится явно через `UUID(...)` в
  `try/except ValueError`, а не передаётся строкой в `session.get()`;
- новый порог или время поведения — в настройки с границами, а не константой в коде;
- цвета и тени — только токенами в `web/src/index.css`. Литеральный цвет в разметке
  ломает вторую тему;
- загрузка экрана — скелетон, а не `LoadingState` на весь экран: строчка «Загрузка…»
  сжимает страницу в одну строку и подвал прыгает.

**Где что лежит:**

| Что | Где |
| --- | --- |
| отбор кандидатов, скоринг виральности | `core/services/scoring.py` |
| доверие источнику | `core/services/trust_score.py` |
| дубли по эмбеддингам | `core/services/dedup.py` |
| рерайт в персону | `core/services/rewrite.py`, `core/services/persona.py` |
| подтемы: подбор, классификация, чередование | `core/services/rubrics.py` |
| партия на день и арифметика долга | `core/services/daily_batch.py` |
| отсев чужой рекламы и пустых постов | `core/services/content_filter.py` |
| ручная генерация «Сделать посты» | `core/services/force_generate.py` |
| публикация и перекрытие рекламы | `core/services/publisher.py`, `core/services/ad_watchdog.py` |
| Markdown → HTML для Telegram | `core/services/tg_format.py` |
| поиск каналов-источников | `core/services/source_discovery.py` |
| задания по расписанию | `scheduler.py` |
| цвета, тени, анимации | `web/src/index.css` |
| общие элементы панели | `web/src/components/ui.tsx` |
| адреса API для панели | `web/src/api/queries.ts` |

**Не расширять задачу по своей инициативе.** Просили кнопку — делать кнопку. Нашли по
дороге настоящую проблему — сказать о ней, а не чинить молча вместе с основной задачей.

## Тесты

Все на реальном Postgres, моков базы нет. Внешние сервисы подменяются фейками.

**Тест должен ловить поведение, а не подтверждать реализацию.**

**Если тест упал — сначала понять, кто прав.** Тест может быть неверным, а может
указывать на настоящий баг. Не подгонять одно под другое, не разобравшись. В этом
проекте уже было: проверка баланса подтем «провалилась» дважды подряд, и оба раза
неверной оказывалась арифметика самой проверки, а не код.

**Куча падений в разных файлах — почти всегда мусор в базе, а не регрессия.**

## Окружение разработки

Песочница пересоздаётся между сессиями — всё ниже приходится делать заново.

```bash
# Postgres и Redis
service postgresql start && redis-server --daemonize yes

# pgvector нужен отдельным пакетом, иначе миграции падают на CREATE EXTENSION
apt-get install -y postgresql-16-pgvector
sudo -u postgres psql -c "CREATE USER nxai WITH PASSWORD 'nxai' SUPERUSER;" \
                     -c "CREATE DATABASE nxai OWNER nxai;"
sudo -u postgres psql -d nxai -c "CREATE EXTENSION IF NOT EXISTS vector;"

# Зависимости. requirements.txt в репозитории НЕТ — ставить по pyproject.toml.
# Проект требует Python 3.12, в песочнице 3.11: ставить зависимости списком,
# а не `pip install .`, иначе упрётся в requires-python.
python -m venv .venv && .venv/bin/pip install <список из pyproject.toml>

cd web && npm install
```

Переменные окружения (минимум, чтобы стартовало):

```bash
export DATABASE_URL="postgresql+asyncpg://nxai:nxai@localhost:5432/nxai"
export REDIS_URL="redis://localhost:6379/0"
export API_SECRET_KEY="dev-secret-key-not-for-prod"
export SECRET_ENCRYPTION_KEY="<32 байта в base64>"
export TELEGRAM_API_ID="12345"      # пустая строка не проходит валидацию pydantic
export TELEGRAM_API_HASH="dev-hash"
export ENVIRONMENT="dev"            # только 'dev' или 'prod', НЕ 'development'
export PYTHONPATH="/path/to/nxai"
```

Админ заводится скриптом, но пароль он спрашивает интерактивно (`--password` нет) —
в неинтерактивной среде проще вызвать `AdminService.create_admin` из короткого скрипта.

**Известные особенности песочницы** — не тратить на них время заново:

- при выставленном `API_SECRET_KEY` падает `tests/test_config.py::test_prod_requires_real_api_secret_key`
  — это артефакт окружения, а не регрессия: без `source` переменных тест зелёный;
- Postgres иногда падает между командами; признак — ошибки подключения в файлах,
  которые вы не трогали. Проверять `pg_isready`, а не искать причину в коде;
- headless Chromium **не рисует** `backdrop-filter`: «жидкое стекло» на снимке не увидеть,
  судить по вычисленным стилям;
- `env(safe-area-inset-bottom)` в браузере равен нулю — отступ под полоску iPhone
  проверяется формулой, а не снимком;
- снимок `full_page` рисует фиксированные элементы в позиции прокрутки — для них
  снимать только видимую область.

## Деплой

Прод-стек — **`docker-compose.prod.yml`** (там nginx и certbot). Простой
`docker-compose.yml` — для разработки, **nginx в нём нет**: команда вида
`docker compose build nginx` без `-f` отвечает «no such service».

```bash
cd /opt/nxai && git pull origin main
docker compose -f docker-compose.prod.yml --env-file .env build migrate api ingest bots scheduler nginx
docker compose -f docker-compose.prod.yml --env-file .env run --rm migrate
docker compose -f docker-compose.prod.yml --env-file .env up -d api ingest bots scheduler nginx
```

Что пересобирать — по тому, чей код изменился:

- сервис в `core/` — все, кто его импортирует: обычно `api` и `bots`, а если его зовёт
  `scheduler.py` (проверить `grep`-ом) — то и `scheduler`. Правка в
  `core/services/daily_batch.py` меняет поведение планировщика, хотя сам `scheduler.py`
  не тронут;
- **новая миграция — обязательно пересобирать `migrate`**. У него свой образ, и сборка
  `api` его не задевает: `up -d migrate` поднимет старый образ, `alembic upgrade head`
  отработает вхолостую и выйдет с нулём. Схема не обновится, а `api` стартует и упадёт
  на отсутствующей колонке. На этом уже попадались;
- миграцию запускать через `run --rm migrate`, а не `up -d`: `up` на уже отработавшем
  сервисе может ничего не сделать, а `run` всегда запускает заново и показывает вывод
  alembic;
- менялся фронтенд — **`nginx`**: статика панели вшита в его образ (`web/Dockerfile`),
  и без пересборки новых страниц в панели не появится. `restart nginx` тут не помогает;
- менялись только `ROADMAP.md` или `docs/` — деплой не нужен, так и сказать.

Правка `deploy/nginx/nginx.conf` пересборки не требует — файл смонтирован volume'ом,
достаточно `exec nginx nginx -t` и `exec nginx nginx -s reload`.
